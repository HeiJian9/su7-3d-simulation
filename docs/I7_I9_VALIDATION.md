# I7–I9 实施与验收 · 0.7.0

2026-10-28，Asia/Shanghai。基线为 `290f1aa` / 0.6.7。演示：[http://localhost:3000](http://localhost:3000)。**本报告按证据分层，已完成核心真人补验，录像归档仍待补齐，不宣称整轮全部通过。**

## 实际实现

共享 `capabilities.ts` 定义 18 项控车工具和严格参数，覆盖 26 个实际可调属性：四窗、四门、前后备箱开度；前灯模式与亮度；转向／双闪；前后主灯开关和亮度；氛围灯开关／颜色／亮度；车漆；雨刷档位／相对／一次；散射开关／强度和夜间观察。`assistant_reply` 负责不执行车辆动作的追问、未知、未支持、否定／取消和交谈。

百炼 `deepseek-v4.1-flash-1017` 是车载智能助手，不仅返回意图标签。实际流程为千问音频转写 → 文本／状态／焦点／上下文 → `tool_calls` → 两端白名单与整轮校验 → VehicleLedger 顺序计算并原子提交 → 驱动到位 → 对应 `tool_call_id` 回传效果及顺序观察 → 模型短答 → 原 CosyVoice。

服务端保存原始协议消息并关联 ID；核对工具完成结果与本轮命令、版本，再生成最终答复。没有 JSON-mode 假降级，也不将模型口头成功当执行。前端继续保留去重、录音代次、过期丢弃、手动抢占、取消、动画改向及属性级完成确认。

新增前灯和前后顶灯亮度已进入状态／Schema／手动滑块／工具／实际灯面、SpotLight、补光及散射。原场景散射与夜间观察也纳入同一领域，移除重复局部状态。一点为集中步长 0.1，雨刷为一档；绝对百分比与相对百分点分开，边界钳制并反馈。

自动路由只快捷执行完整规则；强制 LLM 可证明每项功能真实经过模型。对象不唯一禁止擅自全选，模型越界会先拒绝所有动作，再最多重新发起一次澄清工具调用。取消始终保留本地即时路径。

详见 [工具参数](LLM_TOOLS.md)、[能力矩阵](CAPABILITY_COVERAGE.md)、[机器 Schema](validation/i7-i9/tools.json)、[逐属性机器覆盖](validation/i7-i9/capability-coverage.json)。

## 本地关键词唤醒

采用 sherpa-onnx 2.0.1 / 中文 WenetSpeech 3.3M INT8 模型，在现有本机 Node 独立 Worker 中识别。浏览器音频通过同源本机 WebSocket，未唤醒不调用云 ASR，也不保存原始麦克风音频。不是按钮、定时器或伪造结果触发关键词。

用户开启后有状态和音量输入提示；真实关键词命中后先停止关键词采集，提示音后进入单轮录音。录音、转写、执行、播报期间暂停关键词流；播放结束后释放回声尾音再恢复。隐藏页面停止采集，关闭或卸载终止连接与 Worker。

按用户反馈，开口准备从 5 秒延长为 **15 秒**，单轮从 15 秒延长为 **30 秒**，语音后的静音结束为 **1.5 秒**。这些值由共享 `audio-settings.ts` 统一驱动 VAD、WAV 编码和服务端校验。已有七秒思考后再说话的真实浏览器回归。

当前只承诺“先唤醒，再说命令”。唤醒词与命令连说的固定音源可检测关键词，但本实现会重新打开单轮录音，不能证明后续命令不被截断，所以连说不计通过。也不声称复刻小米专有引擎或锁屏后台常驻。

## 实测发现与修正

1. 百炼工具结果带 `index`，最初严格解析将其误拒；保留协议字段并复测，未退回 JSON 命令。
2. 首次长矩阵有一次相对开度未达预期，保留失败，固定采样温度并重跑对应对话及新版前 40 项。
3. 模型曾把不明确“打开顶灯”扩为两盏。新增两端目标约束、拒绝整轮、一次受控追问修复；真实追问／补答与注入非法目标分别验证。
4. 官方 npm WASM 包依赖 Node 文件系统，浏览器直接运行失败。转为现有本机服务的识别 Worker，明确依赖和资源来源。
5. 真人连接断开反馈促成音频背压／幅度／原因及可见性修正；实际关键词闭环随后留证。
6. 用户指出开口前思考会提前退出，统一延长为 15／30／1.5 秒并增加七秒后开口和长音频测试。
7. 早期完整回归的六个失败是旧版文案断言，与新故障分类不一致；修改后定向复测，保留初始完整日志，不删除红色历史。
