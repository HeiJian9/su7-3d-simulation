# 0.7.3 · 连续灯带、复合指令与自然女声

2026-10-29，基线 `e221e9c` / `v0.7.2-enclosed-cabin`。用户提供前排灯带断点截图，追加多要求语音、自然回复及甜美女声。

## 实际修改

- **前排灯带**：原冠部估算路线只做最近表面投射，左段在仪表罩中途停止，右段起点偏离边缘；三处投射断面使视觉不连续。现沿原 Mesh53 的 25 段原生边缘重建两段窄灯面，在共同顶点连接；不再用平滑曲线切角或跳过断面。宽 2.4 mm、表面偏移 0.55 mm，两段共 561 个截面，无断面、无独立碎片。实际 GLB 贴合与边缘偏差检查独立运行。
- **资产保护**：仅两个自建冠部灯面改变。0.7.2 其余 **152 节点**的几何、父子关系、变换和材质归属签名完全保持；原生面板、显示背光、四轮、雨刷、底板遮光和备箱内衬继续回归。当前 154 节点、141 网格、105,548 三角面、46 材质、15 纹理。唯一工作工程为 `assets/source/blender/su7-enhanced.blend`；正常导出仍用 `npm run asset:export`，不要重复应用一次性修复脚本。
- **一句话多个要求**：继续使用真实 DeepSeek `tool_calls`，完整校验后交统一 Ledger；不同部件同时动画，同一对象 set→adjust 按语义顺序计算。可说“左前窗开到35%，前备箱开到三成，打开蓝色氛围灯并调到四成，再打开雨刷”。仍限制每轮最多 16 条动作，歧义追问，不擅自展开为所有部件。
- **自然回复**：模型总结真实完成回执，用简短亲切中文，合并多项结果。复杂指令沿用工具 ID 逐个回传；规则快捷路径先完成动作，再请求 `/api/assistant/feedback` 组织回复。后者重新核对共享 Ledger 的 revision、effects、boundary，不能作为额外控车通道。规划温度保持 0，回复温度 0.55。手动抢占／新录音／版本改变时丢弃旧回复；自然回复服务失败使用已确认的事实播报，TTS 失败保留文字与重播入口。
- **女声**：当前本机 `.env` 的 `TTS_VOICE=longanhuan`，即百炼“龙安欢”（元气女声），模型仍为 `cosyvoice-v3-flash`。只换音色，ASR、模型服务和已有 Key 保持服务端配置。[官方音色说明](https://help.aliyun.com/zh/model-studio/cosyvoice-voice-list)。[真实 API 试听](assets/trim-dialogue/longanhuan-sample.wav)可直接播放；听感偏好仍以用户体验为准。

## 回归发现并修复

完整浏览器回归另发现旧车窗测试仍使用已隐藏的 FL／RR 后缀定位按钮，实际热点已成功选择车窗；验收定位改为当前可见名称，保留选择、开口命中及拖动不误触的原断言。

另在 1366×768 的追问状态发现右后窗预设按钮被扩大的语音栏挤出面板。仅在短屏且有追问时适当收紧四窗行间距，保持四行预设完整可见，不删除按钮或放宽视口断言。

首次真实固定音频回归中，模型面对“把右前车窗打开，再打开空调”只提出开窗工具，最终回复才承认空调未支持；因此发生部分执行。保留 [首次失败记录](validation/trim-dialogue/live-speech-first-attempt.json)。

追加共享的未实现控车子句保护：显式要求空调、座椅加热／通风、天窗等已知未实现功能时，阻止整个控车批次，向模型按原 tool_call_id 回传“未执行”，要求真实 `assistant_reply/unsupported` 工具重新规划；不把这次拒绝标作执行成功。浏览器独立重复检查，否定子句“别打开空调”不误判。其他未匹配表达仍先交模型，不将规则未命中直接判成不支持。

## 分层证据

- 单元／协议／故障注入：完成回执校验与去重、部分计划拒绝、否定、顺序调整、晚回复、反馈故障兜底；结果见 `validation/trim-dialogue/unit.json`。
- 实际 GLB：`geometry.json` 检查 25 灯面贴合、两段冠部原生边缘和单一连通区域；`enclosures.json` 检查 152 节点保持、12 车轮相交为零、四条脚窝遮光射线和封闭内壁。
- 双分辨率浏览器：1920×1080、1366×768，座舱／风挡俯视、原灯光／门窗／备箱／雨刷、输入、音频资源与两分钟相机持续运行；报告见 `playwright-results.json`。截图存于 `docs/assets/trim-dialogue/`，历史截图不覆盖为新证据。
- **真实 API＋合成固定音源**：`live-speech.json` 保存 Qwen 实际转写、DeepSeek 工具／完成回复、渲染实际值、龙安欢音频实际播放结束及麦克风释放。覆盖多部件、同对象连续调整、自动规则自然回复、混合不支持请求整轮拒绝、一次刮刷后关闭。
- **真人**：本轮未新增真人麦克风或主观听感通过记录。既有 I7–I9 真人及唤醒证据保留，不用合成音源冒充真人。距离／噪声统计按用户要求不在范围。

## Hanser 与使用

用户所指为小爱声音商店 Hanser 联名音色。查阅的[小米音色接口文档](https://developers.xiaoai.mi.com/documents/Home?type=%2Fapi%2Fdoc%2Frender_markdown%2FVoiceserviceAccess%2FDevice%2FReference%2FTTS)没有提供该款公开 ID 或可导出的本地模型，当前百炼预置列表也没有。声音商店的设备内可用音色不等于可直接交给 CosyVoice 的模型；本轮未下载不明格式包，也未宣称接入 Hanser。以后若有兼容 TTS 的可用模型／接口，可再做适配。

演示：http://localhost:3000，刷新后帮助内版本 0.7.3。语音自然说多个要求即可；“操作帮助 → 连接与诊断”仍提供自动／强制 LLM 验证。当前女声可在本机 `.env` 的 TTS_VOICE 切回 `longanyang`，随后重启服务；无须改 Key。

交付包含当前源码、唯一 .blend／GLB、纹理及来源许可、构建、报告与试听；不含 `.env` 或 Key。校验信息以 `deliverables/SU7-0.7.3-manifest.json` 为准。
