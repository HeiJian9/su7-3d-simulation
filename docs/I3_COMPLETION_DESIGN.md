# I3 收尾设计：澄清、自动结束与播报打断

2026-10-26，0.3.2。仅在现有四窗、千问 ASR 与 CosyVoice 上补齐 I3，不接 DeepSeek、不推进 I4。历史由 Git 管理，无旧工程副本。

## 澄清与取消

共享规则只在已有**单一且未过期**的车窗对象时使用省略目标。上一条“全部关闭”等批量操作不作为下一条模糊指令的全体目标；“打开车窗”必须追问。只有明确说“所有／全部”等才批量操作。

待澄清意图保留完整命令，最多两分钟，不先执行其中一部分。用户说“左后那个”后只补齐目标；也可用面板按钮选择。新增“取消这条指令”按钮，语音／文字也支持取消；取消清除待确认意图和旧语音请求，不改变车辆目标，不回滚已接受动作。取消后单说“左后那个”不能继续执行已撤销意图。

支持“右后方的车窗”等常见方向措辞；追问时明确回答“所有车窗／全部”可补全全体目标。这些规则别名不替代大模型兜底。完整设计的规则未命中→DeepSeek 结构化意图→校验器→统一执行器仍留在 I7；I3 未命中时明确提示并保持目标不变，不假装已经调用模型分析。

## 自动结束与资源释放

录音使用本地音量断句，连续有效帧后静音 1.2 秒自动结束；无有效语音 5 秒退出，单次最多 15 秒。WAV 与 WebM 均可手动结束或取消。自动结束不是长期唤醒词功能，也不保证所有噪声环境的表现。

ASR 上传前关闭 AudioContext 并停止所有 MediaStreamTrack。诊断新增 microphone-released，记录 track 数及 readyState 是否均为 ended。取消期间晚到的权限授权也立即释放返回的 track。

WebM 的 stop/onstop 具有异步间隔：取消必须清除旧回调、结算等待 stop 的 Promise；新一轮开始后旧 dataavailable 不得写入新音频，旧 onstop 不得清除新一轮的等待器。新增延迟 onstop 的原生 WebM 浏览器回归覆盖快速取消／重录。

## 播报打断与旧结果隔离

新录音先同步暂停 HTMLAudio、清空音源并回收 Blob URL，终结旧播放 Promise，再进入录音初始化。播放器返回真实 wasPlaying 和已播放毫秒，只有实际播放被打断才记录 tts-stopped。

实际播放被打断时留 180ms 短缓冲，再获取麦克风；缓冲期间取消会阻止后续 getUserMedia。麦克风继续开启 echoCancellation／noiseSuppression。此顺序减少自身播报被重新录入，真实扬声器与房间回声由真人复验，不能用代码顺序替代物理环境验证。

每轮仍使用 generation、录音开始时车辆 revision／epoch 和请求 ID 三重保护。新的手动／文字操作、取消或重录都会作废旧响应。ASR 结果记录实际 transcript，规则提交记录完成的各窗开度，TTS 播放开始／结束与暂停分别记录，便于核对整个过程。

## 验证分层与验收

| 层次 | 证据边界 |
|---|---|
| 单元及隔离浏览器 | 追问／取消／批量对象、180ms 内取消、WebM 晚回调、故障注入和旧结果；不读取用户 Key |
| 真实 API + 合成音源 | 真实千问转写、CosyVoice、追问回答、实际几何、两次 HTMLAudio 暂停及录音先后顺序；humanMicrophone=false |
| 真人设备 | 用户在当前演示中自动结束→追问→回答→播报时重录→取消，并保存诊断与主观听感确认 |

真实 API 自动测试为 `npm run speech:verify-i3`，会产生少量实际调用，输入音源为合成语音；普通 `npm run test:e2e` 始终使用 3003 无凭据隔离服务。结果写入 `docs/validation/i3-final/`，真人结果独立列出。全部达到当前四窗增量验收后才勾选 I3，后续仍等待用户体验与 I4 授权。
