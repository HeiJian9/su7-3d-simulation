# 0.8.3 · 迎宾重置、长距离矩阵光与独立 Logo 控制

2026-10-30。根据用户五项反馈，主展示页刷新恢复默认迎宾状态，延长流星雨并补齐中央，增强灯口薄雾，为四门地面 Logo 增加独立开关、亮度与语音工具，并解释自动解锁迎宾。

## 使用

- 主展示页载入会清除持续流星雨和旧迎宾事件，流星雨亮度恢复 100%，默认解锁、自动迎宾开启。与车窗、车门等部件一样重新开始。SSE 临时断线重连及 `/remote` 遥控页刷新不执行重置。多开一个主展示页也会重置共享迎宾服务，遥控页继续同步当前主展示。
- 流星雨光纹从前灯附近延伸到根坐标 z=−14.5 m，约车头前 12 米。左右图案保持镜像，加入中轴与近中轴光纹，消除原有固定中央空带。远端有自然衰减，不是整片同亮地毯。
- 八个矩阵模组逐帧取实际 LED 实例位置作为薄雾源，增强低密度雾光。雾场使用半分辨率、32 次带抖动积分及浮点缓冲合成，减轻原远距积分的层纹；清晰矩形仍投到地面。沿用“丁达尔光束／空气散射”总开关和强度。
- “车门 Logo 迎宾灯”统一控制四个门底灯口、字标、光晕和迎宾雾光。默认允许开门点亮；关闭投影不会关门，打开投影不会开门。投影亮度 0–100%，关闭时调亮度仍不点亮。调节经过统一命令校验，并等待灯光驱动收敛后完成回执。
- “解锁时播放迎宾动画”模拟接近并解锁车辆时的短迎宾。先关闭持续流星雨，再点“锁定车辆 → 解锁车辆”，播放约 5 秒后结束；关闭此选项就不自动播放。直接“流星雨迎宾”适合持续展示，两种用途不同。

可说“关闭 Logo 迎宾灯”“迎宾投影亮度设为百分之四十”“打开迎宾地毯灯”“再暗一点”“查询迎宾投影亮度”，也可说“关闭 Logo 迎宾灯，同时打开流星雨大灯”。不明确的“迎宾灯”在缺乏唯一上下文时应追问，不能混淆车前与车门灯。

## 工具和状态

共享注册表增加 `vehicle_welcome_logo_switch`（welcomeLogo / doors / enabled，set、query）和 `vehicle_welcome_logo_brightness`（welcomeLogo / doors / brightness，set 0–1、adjust −1–1、query），共 22 项控车工具及 assistant_reply。Schema、规则、LLM、面板与 VehicleLedger 使用同一命令；工具执行成功依据实际渲染驱动，回传原 tool_call_id。完整定义见 [tools.json](validation/welcome-controls/tools.json)。

刷新重置是主页面每次实际文档载入的一次操作，React StrictMode 重放不重复重置。服务端序号保持递增、重试去重保持；断线重连不会变成新一轮自动迎宾。原基础模型及门窗／灯带／转向／雨刷机构不修改。

## 证据

最终计数见 [summary.json](validation/welcome-controls/summary.json)。118 项单元、24 项双分辨率浏览器、类型／规范／生产构建及资产保护检查通过。另以无凭据服务持续开启30秒，本机 Edge 无头模式1920×1080预热后帧率中位202、最低195，关闭后停止且无浏览器错误，见 performance.json；该短时样本不能代表录屏、其它硬件或长时间表现。自动浏览器使用无凭据 3003；真实 API 音源测试使用已配置的 3000，两者不混用。

新增浏览器检查实际刷新／遥控刷新、默认值、锁定解锁单次结束、Logo 满亮／40%／相对调节／关闭／关门门控，以及远端 z&lt;−11 m 与中央区域的真实亮像素。相机不因灯光开关自动变化，原近远光和双闪回归继续。

真实语音八轮全部通过，保存于 [live-speech.json](validation/welcome-controls/live-speech.json)：千问 ASR → 百炼 DeepSeek 原生 tool_calls → 实际灯光与逐 ID 结果 → CosyVoice 播放，使用固定合成输入，不能替代真人。每轮包含实际投影亮度与完成回执，TTS 结束和录音轨道释放单独核对。

本轮不增加真人通过声明，不模拟距离或噪声，不操作用户录屏或编造录像偏移。雾光仍是八组代表性源和两路地面 gobo 的实时近似；不是 96 路物理路径追踪。
