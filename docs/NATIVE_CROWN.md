# 0.7.8 · 原车仪表台饰边发光

2026-10-29。用户近景指出仪表台灯带高出门板，接头有台阶，并明确要求直接在原车线条上发光。

此前沿结构网格 Mesh53 新增浅圆弧扩散面，虽贴合距离及端点中心线检查通过，真实可见截面仍高于门板；这些检查不足以证明接头观感。进一步查明原车可见的饰边是覆盖在 Mesh53 上的 **Mesh54**，使用与门饰边相同的原图集。此前在 Mesh53 上直接发光被上层饰边遮挡，不代表原车饰边不能发光。

本轮移除两个 crown 附加面的运行时使用，删除截面生成器、衍生几何和替换绑定。改在 Mesh54 的左右原生边缘区域发光，原三角形、顶点位置、法线、UV 和材质纹理均保持。与前门上沿使用一致的表面选区和 1.8 发光倍率，覆盖完整可见饰边而非只照亮上缘细线。8.5 mm 是表面选区半径，不是新增几何的宽度或抬高量。原车饰边在极近视角仍能看到原图集缝线与原模型折角。

31 条原生路径分布在 11 个原网格上，加两条保留的仪表台下沿灯面，共 33 条覆盖；前后门板、拉手、扬声器与中央箱体的灯线保持。五个空气光场由当前路径生成，crown 不再采样已隐藏的附加面。颜色、亮度、开关及车门随动继续共用既有车辆状态。

路径只读来自当前 `.blend`，用 `scripts/derive-native-ambient.py` 生成，不保存或导出模型。唯一 Blender 和 GLB 保持；GLB SHA256 `05f7301a57afd0e0f4abbadab5cc57d6300f9d900ceb065d4a779d6134ad826a`。正常模型导出继续 `npm run asset:export`。

本轮证据保存在 `validation/native-crown/`，截图在 `assets/native-crown/`：全舱 40%／65%、关闭状态、左右接头 20 cm 相机近景，均使用真实运行 GLB 和现有自由镜头操作；未注入替代场景或修改相机内部状态。单元直接核对所有路径属于真实三角形边、原顶点／法线／UV／索引保持、两端与门饰边误差小于 0.05 mm、退出恢复原材质和几何。

106 项单元／协议测试、22 项双分辨率浏览器回归，以及类型、规范、生产构建、资产和保密检查通过；机器记录见 `validation/native-crown/summary.json`。自动截图及图像核查不替代用户主观视觉验收；本轮没有新增真人麦克风或真实 API 证据。既有音色、助手、唤醒和资产修正沿用此前结果。
