# 0.8.0 · 流星雨迎宾与四门 Logo 投影

2026-10-30，基于当前 0.7.8 增量实现。原有转向灯严格保持，新增功能不依赖云端 API。

## 执行顺序与结构

1. 核对当前原生前灯、车门父子层级、材质和状态驱动；确认原有八个 Mesh61 投射面及 Mesh70 外透镜。未发现通用远程控车或锁态服务，既有 WebSocket 仅服务关键词唤醒。
2. 在原八个投射模组内增加独立 LED 微单元与光学收口；沿原门底表面定位四个独立图案投影光源。
3. 迎宾动画按事件时间在本地计算，增加手动／解锁入口，在现有 Express 服务上增加小型 SSE 事件通道及独立遥控页面。
4. 验证几何位置、逐单元动画、真实投影像素、门运动、远程协议和原功能；双分辨率回归及交付结果见 validation/welcome/。

## 模型与灯光

- 每个原投射模组增加 4×3 个圆角实体 LED，共八组／96 个单元。每组采用 InstancedMesh，单元拥有独立发光参数；另有八个椭圆金属光学收口。所有坐标和方向从实际运行 GLB 原投射面推导，见只读脚本 `scripts/derive-welcome-lamps.mjs` 与 `apps/web/src/data/welcome-lenses.json`。
- 单元 footprint 位于原模组面域内；新光学面沿前向仍位于原 Mesh70 透镜后方。原车身、灯壳外轮廓、所有转向灯及机构几何不改。新增几何在运行时生成，基础 `.blend`、GLB、纹理字节保持，未重跑导入或分件脚本。
- 每侧模组 0／1 为近光、2／3 为远光。近光只点亮对应模组；远光同时保持近光点亮。现有三个控制入口、亮度和执行器保持，映射只改四个 highOnly 标志。
- 迎宾长 4.8 秒，包含正向星点扫描、反向扫描、柔和聚亮及消退。模组、列、行具有空间对应的时间差，左右共用事件时间。单元不是对整个灯壳统一调亮；结束平滑返回当前正常状态。动画期间改变远近光后，以最新状态为准。
- Bloom 只采新迎宾 LED，先采不透明深度，再模糊叠加，强度受限；原转向灯不进入该 Bloom 蒙版。既有转向材质、颜色、位置、0.72 秒节奏、原体积光代码均保持。

奔驰官方的 [DIGITAL LIGHT 介绍](https://media.mercedes-benz.com/en/press-kit/71dc2a9c-34c7-47e0-a264-d39d89b85d4c/article/6f606abe-092d-4619-8ffc-742a1a10333f)将 Digital Rain／Star Wave 作为迎宾灯光动画。本项目参考其逐级流动和柔和收尾的风格，在现有 SU7 原灯腔内实现独立矩阵灯光。

## 四门投影

四个独立 SpotLight 使用实时生成的 SU7／XIAOMI 黑白图案作为 gobo；每个光源位置来自对实际车门底面的射线测量，向下投射。小型投影器外壳留在对应车门底部，光源世界姿态每帧从真实门矩阵计算，投影文字朝向随门调整。门实际开度超过起始阈值后渐亮，关闭时渐暗。

投影通过真实聚光灯贴图、阴影和地面受光完成。四个投影灯采用独立照明通道：复用原网格作为阴影遮挡体，并使用主场景不透明深度遮挡地面投影，因此不会把文字覆盖到车身上。投影落在同一水平地面，不用悬浮文字牌。首次试验将四个 gobo 灯直接加入主场景，超过常见 16 个纹理采样器上限；现已隔离，未删除既有灯光来规避问题。

## 操作与远程

“灯光外观”顶部：流星雨迎宾、锁定／解锁车辆、解锁自动迎宾、迎宾视角、灯组细节、左右投影视角。

默认锁态为解锁。先锁定，再解锁，启用自动迎宾时播放一次；重复解锁不重播。锁态用于迎宾事件，不自动替用户调整门窗。手动迎宾可以随时触发。开任一车门自动显示对应投影。

“连接遥控器”生成独立配对页面链接。遥控页仅发送动作，三维页通过 SSE 接收含 ID、序号、开始时间的事件，在本地计算 96 个单元的光强；不传输每帧颜色。重复 requestId 在最近 256 次请求内去重；重复快照不重启时间线。过期事件、晚加入页面不重播。服务重启通过 sessionId 切换状态；连接中断会显示文字并重连。

同机：直接打开配对链接，可在另一浏览器或窗口控制当前三维页。

局域网 HTTP 遥控兼容无 randomUUID 的非安全上下文，以 getRandomValues 生成请求 ID。自动浏览器已通过实际 WLAN 地址验证；测试浏览器仅为该检查直连局域网，不改系统代理。访问时应选择电脑 Wi-Fi／以太网地址，避开 VPN／虚拟机适配器地址。

局域网手机：启动前在 PowerShell 设置 `$env:HOST='0.0.0.0'`，执行 `npm start`，用电脑局域网 IP 替换配对链接中的 localhost；保留端口、路径及配对参数。三维页继续在本机打开，手机只打开轻量遥控页。默认仍仅监听 127.0.0.1；远程请求需要本机生成的随机配对令牌，令牌在服务重启后失效。此入口用于可信局域网，不作为互联网部署方案。API Key 不进入遥控链接。

接口：`GET /api/welcome/state`、`GET /api/welcome/events`、`POST /api/welcome/action`；动作仅 play／lock／unlock／auto，严格校验参数。`GET /api/welcome/pair` 只允许本机取配对令牌。SSE 最多 20 连接、慢客户端断开，页面卸载释放连接，投影和 Bloom 卸载释放 GPU 资源。现有语音与助手接口不改；新增迎宾当前通过面板和遥控触发。

## 验收范围与证据

| 要求 | 实现及证据 |
|---|---|
| 转向灯严禁修改 | protected-baseline.json：原 GLB／Blender、AppearanceMechanism、VolumetricLights 与原转向映射保持；native-lamps / appearance 浏览器检查实际颜色和闪烁 |
| 车身、灯廓和门机构保留 | 原模型字节与 VehicleMechanism 不变；mechanical / physical-fixes / wipers 回归 |
| 独立远近光，远光保留近光 | welcome 浏览器检查实际四个近光面＋四个远光面，动画中途切换及结束后状态 |
| 多组空间单元、左右同步、渐亮渐暗 | 96 个实例、实际原面域与外透镜定位检查；连续帧实际单元参数、扫描近景截图；meteorPower 连续性测试 |
| 原状态恢复 | 动画不改 VehicleLedger 灯光状态，末段融合回当前正常值；浏览器验证 |
| 四门独立投影、随门移动、贴地及淡出 | welcome 逐门半开／全开／关闭、其余三门零功率、真实地面亮像素差分及左右截图 |
| 手动、解锁、远程事件触发 | WelcomeController 单元、实际 HTTP＋SSE 协议、独立遥控页与渲染页双页面测试 |
| 远程访问边界 | 实际局域网地址请求：未配对拒绝、已配对可读；外源 Origin 和无效参数拒绝 |
| 无纹理超限、适度 Bloom、无覆盖 | 浏览器捕获 pageerror／console error；真实投影和灯组近景核查，新增独立渲染通道 |

本轮测试是无凭据环境中的真实 GLB／WebGL 和真实本机 HTTP＋SSE，不称为真人或手机实体设备验收；既有语音真实 API 及真人记录继续保留。运行时几何参数包含在交付包，基础 `.blend` 保持原资产。正常基础模型导出仍用 `npm run asset:export`；模型发生变化后须重新运行只读 derive-welcome-lamps 并复验。

最终测试数量、保护哈希和交付校验见 `validation/welcome/summary.json` 及 deliverables 对应 manifest。

最终结果：111 项单元／协议测试、32 项双分辨率核心回归、2 项实际局域网 HTTP 浏览器验证通过；连接清理另有 2 项定向复验通过。类型、规范、构建、资产与保密检查通过。
